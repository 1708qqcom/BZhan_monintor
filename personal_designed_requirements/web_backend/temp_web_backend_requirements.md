# Feature Requirements - Web Backend

## Background

当前 B站UP主监控服务是命令行工具，用户需要：
- 手动编辑 YAML 配置文件修改设置
- 无法直观查看监控状态和推送历史
- 无法灵活添加/移除监控的 UP主

需要一个 Web 管理后台提供可视化操作界面。

## Goal

为监控服务提供 REST API 后端，支持：
1. UP主管理（查看、添加、移除）
2. 推送历史查询（分页、筛选）
3. 配置管理（查看、修改）
4. 登录状态管理（查看状态、获取二维码）

## User Story

**As a** B站重度用户  
**I want** 通过 Web 界面管理监控任务  
**So that** 我可以方便地添加/移除 UP主、查看推送历史、调整监控配置

## Functional Requirements

### FR-001: UP主管理

**GET /api/ups**
- 获取监控中的 UP主列表
- 支持按状态筛选（监控中/已暂停）
- 返回：UP主ID、名称、头像、监控状态、添加时间

**POST /api/ups**
- 添加 UP主到监控列表
- 输入：UP主 mid（B站用户ID）
- 系统调用 B站 API 验证 mid 有效性并获取名称、头像
- 返回：添加成功的 UP主信息

**DELETE /api/ups/{id}**
- 移除 UP主（软删除，设置 is_monitoring=0）
- 该 UP主的历史推送记录保留

### FR-002: 推送历史查询

**GET /api/videos**
- 获取视频推送历史记录
- 支持分页（page, page_size）
- 支持筛选：UP主ID、日期范围、是否已推送
- 返回：视频标题、BV号、UP主、发布时间、播放量、推送时间

### FR-003: 配置管理

**GET /api/config**
- 获取当前配置
- 返回：检查间隔、最多监控UP主数、飞书 Webhook URL

**PUT /api/config**
- 修改配置
- 输入：配置项键值对
- 验证：检查间隔 ≥ 5分钟、Webhook URL 格式
- 配置更新后，监控进程下次循环自动生效

### FR-004: 登录状态管理

**GET /api/login/status**
- 查询当前登录状态
- 返回：是否已登录、Cookie 过期时间、当前用户名

**GET /api/login/qrcode**
- 获取登录二维码
- 返回：二维码图片 URL、auth_code
- 前端轮询登录状态

### FR-005: 健康检查

**GET /api/health**
- 服务健康检查
- 返回：服务状态、数据库连接状态

## User Flow

### 添加 UP主 流程

```
用户访问 Web 管理页面
  → 点击"添加 UP主"
  → 输入 UP主 mid 或主页链接
  → 点击确认
  → 系统验证 mid 有效性
  → 显示 UP主 名称和头像供确认
  → 用户确认添加
  → UP主 加入监控列表
```

### 修改配置流程

```
用户访问配置页面
  → 修改检查间隔（如 30分钟 → 60分钟）
  → 点击保存
  → 系统验证参数有效性
  → 更新数据库配置
  → 监控进程下次循环自动读取新配置
```

## Edge Cases

### EC-001: 添加无效 UP主

- 用户输入不存在的 mid
- 系统调用 B站 API 返回错误
- 提示"UP主不存在，请检查 ID 是否正确"

### EC-002: Cookie 过期

- 用户查询登录状态时发现 Cookie 已过期
- 显示"需要重新登录"
- 用户点击"重新登录"获取二维码

### EC-003: 数据库锁定

- Web API 写入时监控进程也在写入
- SQLite 返回 SQLITE_BUSY 错误
- 使用 WAL 模式和重试机制解决

### EC-004: B站 API 限流

- 添加 UP主 时触发限流
- 返回"请求过于频繁，请稍后重试"
- 复用现有重试机制

## Acceptance Criteria

### AC-001: UP主管理

- [ ] 可查看当前监控的所有 UP主
- [ ] 可通过 mid 添加新 UP主（验证有效性）
- [ ] 可移除 UP主（保留历史记录）

### AC-002: 推送历史

- [ ] 可分页查看推送历史
- [ ] 可按 UP主 筛选
- [ ] 可按日期范围筛选

### AC-003: 配置管理

- [ ] 可查看当前配置
- [ ] 可修改配置并立即生效（下次循环）

### AC-004: 登录状态

- [ ] 可查看当前登录状态
- [ ] 可获取登录二维码
- [ ] 扫码后自动更新 Cookie

### AC-005: 数据迁移

- [ ] 现有 JSON 数据成功迁移到 SQLite
- [ ] 迁移前后记录数一致
- [ ] 迁移后 JSON 文件保留备份
