# Feature Requirements

## Background

当前系统已实现 B站 UP主视频监控和自动推送到飞书的功能。但用户无法手动选择某个视频推送到飞书，只能依赖系统自动检测新视频后推送。

在某些场景下，用户可能需要：
- 重新推送某个已发布的视频（例如飞书消息被误删）
- 手动推送历史视频到飞书群
- 测试飞书 Webhook 是否正常工作

因此需要提供手动推送功能。


## Goal

在 UP主管理页面（`/ups`）的最新视频列表中，为每个视频提供手动推送到飞书的功能。

核心目标：
1. 用户可一键推送视频到飞书
2. 推送操作有明确的成功/失败反馈
3. 推送历史可追溯
4. 支持重复推送


## User Story

**As a** 系统管理员

**I want** 在 UP主管理页面手动推送某个视频到飞书

**So that** 我可以灵活控制推送内容，应对误删、测试、历史视频推送等场景


## Functional Requirements

### FR-001: 推送按钮显示

**描述**：在每个视频卡片右上角显示"推送"按钮

**详细说明**：
- 按钮位于视频卡片右上角，不影响原有的"点击跳转到B站"功能
- 按钮文案："推送"
- 鼠标悬停显示提示："推送到飞书"
- 按钮样式与页面整体风格一致（使用 bilibili-pink 主题色）

**位置**：
- 桌面端：视频卡片右上角
- 移动端：视频卡片右上角（适当增大点击区域）


### FR-002: 推送操作

**描述**：点击推送按钮后，触发推送流程

**详细说明**：
- 点击前弹出确认对话框：`确定推送视频 "{title}" 到飞书？`
- 用户确认后开始推送
- 推送过程中按钮显示加载状态，防止重复点击
- 推送成功后显示成功提示（3秒后自动消失）
- 推送失败后显示失败提示（包含错误原因）


### FR-003: 重复推送

**描述**：允许对已推送的视频再次推送

**详细说明**：
- 不限制推送次数
- 已推送的视频按钮依然可用
- 每次推送都记录到推送历史


### FR-004: 推送历史记录

**描述**：在数据库中记录每次推送操作

**详细说明**：
- 新建 `push_history` 表存储推送历史
- 记录字段：
  - `id`: 主键
  - `video_id`: 关联视频记录
  - `pushed_at`: 推送时间
  - `push_type`: 推送类型（`auto` 自动推送 / `manual` 手动推送）
  - `success`: 是否成功
  - `error_message`: 失败原因（如失败）
  - `created_at`: 记录创建时间
- 支持查询某个视频的推送历史


### FR-005: 视频信息补全

**描述**：推送前检查视频信息完整性，缺少字段时调用 B站 API 补全

**详细说明**：
- 检查字段：`title`、`url`、`pub_time`、`view_count`
- 如果字段缺失，调用 B站 API 获取视频详情
- 补全后更新数据库
- 补全失败时记录日志，推送可继续（使用默认值）


### FR-006: 推送失败处理

**描述**：推送失败时提供明确的错误信息

**详细说明**：
- 后端记录详细错误日志（时间、错误类型、堆栈）
- 前端显示用户友好的错误提示：
  - 飞书 Webhook 未配置："请先配置飞书 Webhook"
  - 视频不存在："视频记录不存在"
  - 网络错误："推送失败，请稍后重试"
- 无需自动重试，用户可手动重新点击推送


## User Flow

```
用户访问 /ups 页面
  ↓
展开某个 UP主的最新视频列表
  ↓
找到目标视频卡片
  ↓
点击右上角"推送"按钮
  ↓
弹出确认对话框
  ↓
用户点击"确定"
  ↓
前端显示加载状态
  ↓
调用后端 API: POST /api/videos/{bvid}/push
  ↓
后端执行：
  - 检查视频信息完整性
  - 如缺失字段，调用 B站 API 补全
  - 初始化飞书推送器
  - 发送推送消息
  - 记录推送历史到数据库
  ↓
返回推送结果
  ↓
前端显示成功/失败提示
```


## Edge Cases

### EC-001: 飞书 Webhook 未配置

**场景**：用户未在配置页面设置飞书 Webhook URL

**处理**：
- 后端检查配置表，发现 `feishu_webhook` 为空
- 返回 400 错误，提示："请先在配置页面设置飞书 Webhook"
- 前端显示错误提示


### EC-002: 视频记录不存在

**场景**：数据库中找不到对应的 bvid 记录

**处理**：
- 后端返回 404 错误
- 前端显示："视频不存在，请刷新页面后重试"


### EC-003: B站 API 调用失败

**场景**：补全视频信息时调用 B站 API 失败（网络错误、Cookie 过期等）

**处理**：
- 后端记录警告日志
- 使用数据库中的现有信息推送（即使不完整）
- 如果数据库中也缺少关键字段（如 title），返回错误


### EC-004: 飞书推送失败

**场景**：飞书 Webhook 调用失败（网络错误、Webhook 失效等）

**处理**：
- 后端记录错误日志（详细异常信息）
- 推送历史记录 `success=false`，保存错误信息
- 前端显示："推送失败，请稍后重试"


### EC-005: 用户取消推送

**场景**：用户点击推送按钮后，在确认对话框中点击"取消"

**处理**：
- 关闭对话框，不执行任何操作


### EC-006: UP主信息缺失

**场景**：视频记录存在，但关联的 UP主信息缺失（数据库异常）

**处理**：
- 后端记录警告日志
- UP主名称使用默认值："未知UP主"
- 继续推送


## Acceptance Criteria

### AC-001: 推送按钮可见性

**验证**：访问 `/ups` 页面，展开任意 UP主的最新视频列表

**预期**：每个视频卡片右上角显示"推送"按钮


### AC-002: 推送成功流程

**验证**：点击"推送"按钮，确认推送

**预期**：
1. 显示加载状态
2. 推送成功后显示成功提示
3. 飞书群收到视频通知卡片
4. 数据库 `push_history` 表新增一条记录


### AC-003: 推送失败提示

**验证**：断开网络后点击推送

**预期**：显示"推送失败，请稍后重试"


### AC-004: 重复推送

**验证**：对同一视频推送两次

**预期**：
1. 两次推送都成功
2. 飞书群收到两条消息
3. 数据库有两条推送历史记录


### AC-005: 推送历史查询

**验证**：查询数据库 `push_history` 表

**预期**：包含以下字段：
- `id`
- `video_id`
- `pushed_at`
- `push_type`（值为 `manual`）
- `success`
- `error_message`
- `created_at`


### AC-006: 视频信息补全

**验证**：手动修改数据库，删除某个视频的 `view_count` 字段，然后推送

**预期**：
1. 后端日志显示"调用 B站 API 补全视频信息"
2. 推送成功
3. 数据库中该视频的 `view_count` 已更新


### AC-007: 未配置 Webhook

**验证**：删除配置表中的 `feishu_webhook`，然后推送

**预期**：显示"请先在配置页面设置飞书 Webhook"
