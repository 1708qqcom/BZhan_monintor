# Feature Requirements

## Background

当前系统已经实现了B站UP主视频监控和飞书推送功能，但缺少对用户"稍后再看"列表的管理。用户在B站标记的"稍后再看"视频容易被遗忘，需要一个系统化的提醒机制。

通过实际验证，B站提供以下可靠的API接口：
- `https://api.bilibili.com/x/v2/history/toview` - 获取稍后再看列表
- 需要登录Cookie（SESSDATA）
- 返回视频标题、BV号、UP主等信息

## Goal

将B站"稍后再看"功能集成到监控系统中，提供：
1. 可视化管理界面（用户查看自己的列表）
2. 定时提醒机制（每天21点推送前3个视频）
3. 手动推送能力（管理员可触发推送）

## User Story

**普通用户**：
- As a: 普通用户
- I want: 查看我在B站标记的"稍后再看"视频列表
- So that: 我可以知道有哪些视频待观看，避免遗忘

**管理员 - 查看**：
- As a: 系统管理员
- I want: 查看所有用户的"稍后再看"列表
- So that: 我可以了解用户的使用情况

**管理员 - 推送**：
- As a: 系统管理员
- I want: 手动推送指定用户的稍后再看视频到飞书
- So that: 我可以在需要时主动提醒用户观看

**系统 - 定时推送**：
- As a: 系统
- I want: 每天21点自动推送每个用户稍后再看的前3个视频
- So that: 用户可以按时收到提醒，提高观看率

## Functional Requirements

### FR-001: 用户查看自己的稍后再看列表
- **优先级**: P0
- **描述**: 用户登录后，可以查看自己的B站"稍后再看"视频列表
- **输入**: 无
- **输出**: 视频列表（标题、BV号、UP主、添加时间、播放量）
- **权限**: 仅查看自己的数据

### FR-002: 管理员查看所有用户的稍后再看列表
- **优先级**: P1
- **描述**: 管理员可以查看所有用户的稍后再看列表
- **输入**: 可选的用户筛选
- **输出**: 分用户的视频列表
- **权限**: 仅管理员

### FR-003: 每天21点自动推送
- **优先级**: P0
- **描述**: 系统每天21:00自动推送每个用户稍后再看的前3个视频到飞书
- **触发**: 定时任务（cron: `0 21 * * *`）
- **输出**: 飞书卡片消息
- **内容**: 视频标题、UP主、观看链接
- **条件**:
  - 用户已配置飞书Webhook
  - 用户的B站Cookie有效
  - 稍后再看列表不为空

### FR-004: 管理员手动推送
- **优先级**: P1
- **描述**: 管理员可以手动触发推送指定用户的稍后再看视频
- **输入**:
  - 目标用户ID（可选，不填则推送自己的）
  - 推送数量（可选，默认3个）
- **输出**: 飞书推送成功/失败状态
- **权限**: 仅管理员

### FR-005: 推送历史记录
- **优先级**: P2
- **描述**: 记录每次推送的历史，包括推送时间、用户、视频列表
- **输入**: 自动记录
- **输出**: 推送历史查询界面

## User Flow

### 流程1: 普通用户查看稍后再看
```
用户登录 → 进入"稍后再看"页面 → 系统调用B站API → 展示视频列表
```

### 流程2: 管理员查看所有用户数据
```
管理员登录 → 进入"用户管理" → 选择"稍后再看"标签 → 展示所有用户数据
```

### 流程3: 定时推送（自动化）
```
21:00触发 → 遍历所有用户 → 验证Cookie → 调用API获取列表 → 取前3个视频 → 飞书推送 → 记录日志
```

### 流程4: 管理员手动推送
```
管理员登录 → 进入"稍后再看管理" → 选择目标用户 → 点击"立即推送" → 系统推送 → 展示结果
```

## Edge Cases

### EC-001: 用户Cookie失效
- **场景**: 用户B站登录过期
- **处理**: 显示"Cookie失效，请重新登录"提示
- **影响**: 无法获取稍后再看列表，自动推送跳过该用户

### EC-002: 稍后再看列表为空
- **场景**: 用户没有标记任何稍后再看视频
- **处理**: 显示空状态提示"暂无稍后再看视频"
- **推送**: 不推送，记录日志

### EC-003: 用户未配置飞书Webhook
- **场景**: 用户没有设置推送地址
- **处理**: 自动推送跳过该用户，记录警告日志

### EC-004: API请求失败
- **场景**: B站API超时或返回错误
- **处理**: 重试机制（最多3次），失败后记录错误日志

### EC-005: 跨时区用户
- **场景**: 用户在不同时区，21点推送可能不合适
- **处理**: 第一期使用系统时区（北京时间），后续可扩展用户级时区配置

## Acceptance Criteria

### AC-001: 用户查看功能验收
- [ ] 用户可以登录系统
- [ ] 用户可以进入"稍后再看"页面
- [ ] 页面正确展示自己的稍后再看视频列表
- [ ] 视频信息包含：标题、BV号、UP主、播放量
- [ ] 列表按添加时间倒序排列

### AC-002: 管理员查看功能验收
- [ ] 管理员可以查看所有用户的稍后再看列表
- [ ] 可以按用户筛选
- [ ] 显示用户名和对应的视频列表

### AC-003: 定时推送验收
- [ ] 系统在每天21:00自动触发推送
- [ ] 推送消息正确展示视频标题和链接
- [ ] 推送成功/失败记录到日志
- [ ] Cookie失效的用户被正确跳过

### AC-004: 手动推送验收
- [ ] 管理员可以选择目标用户
- [ ] 点击"推送"按钮后立即触发推送
- [ ] 显示推送结果（成功/失败）
- [ ] 推送记录可查询

### AC-005: API集成验收
- [ ] 使用已验证的API端点
- [ ] Cookie正确传递
- [ ] 响应数据正确解析
- [ ] 错误情况正确处理

## Non-Functional Requirements

### NFR-001: 性能要求
- API请求超时时间：10秒
- 页面加载时间：< 3秒
- 支持并发用户查看：10+

### NFR-002: 可靠性要求
- API重试机制：最多3次
- 推送失败记录日志，不中断其他用户推送
- Cookie失效告警

### NFR-003: 安全要求
- 用户数据隔离：普通用户只能查看自己的数据
- 管理员权限验证：手动推送需管理员权限
- Cookie加密存储

## Out of Scope

以下功能暂不实现：
- 添加/删除稍后再看视频（仅同步B站数据）
- 视频观看进度同步
- 自定义推送时间
- 多时区支持
- 推送频次限制（防骚扰）
