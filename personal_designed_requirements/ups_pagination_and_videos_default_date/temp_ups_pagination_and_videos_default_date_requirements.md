# Feature Requirements


## Background

当前 UP主管理页面（`/ups`）一次性加载所有 UP主数据，当 UP主数量较多时会导致：
- 页面加载速度慢
- 大量数据传输消耗带宽
- 前端渲染性能问题

当前推送历史页面（`/videos`）的日期选择器默认为空，用户每次打开页面都需要手动选择日期才能查看今日推送记录，操作繁琐。


## Goal

1. **UP主管理页面分页懒加载**：每次加载 20 条记录，滚动到底部自动加载更多
2. **推送历史日期默认今天**：打开页面时，开始日期和结束日期默认设置为当天


## User Story

**UP主管理页面**：
- As a: 系统用户
- I want: 快速查看 UP主列表，不需要等待全部数据加载
- So that: 提升页面响应速度和使用体验

**推送历史页面**：
- As a: 系统用户
- I want: 打开推送历史页面就能看到今日推送记录
- So that: 减少手动操作，快速查看最新推送


## Functional Requirements

### FR-001: UP主列表分页加载

- 后端 API 支持分页参数：`page`、`page_size`
- 默认每页 20 条记录
- 支持通过 `keyword` 参数进行后端搜索
- 返回数据包含 `total` 总数和 `items` 列表


### FR-002: UP主列表懒加载

- 前端初始加载第一页数据
- 滚动到底部时自动加载下一页
- 显示加载状态提示（加载中...）
- 全部加载完毕时显示"已加载全部"提示
- 加载过程中禁止重复请求


### FR-003: UP主后端搜索

- 搜索框输入内容实时调用后端 API
- 搜索结果支持分页懒加载
- 搜索框清空时恢复全量分页数据


### FR-004: 推送历史日期默认值

- 页面加载时，开始日期和结束日期自动设置为当天
- 数据加载自动使用今日日期筛选
- 重置按钮恢复到当天日期（而非清空）


## User Flow

### UP主管理页面

```
打开页面
    ↓
加载第一页数据（20条）
    ↓
显示 UP主列表
    ↓
用户滚动到页面底部
    ↓
自动加载下一页
    ↓
追加显示新数据
    ↓
继续滚动或搜索
```


### 推送历史页面

```
打开页面
    ↓
日期自动设置为今天
    ↓
自动加载今日推送数据
    ↓
用户可修改日期筛选其他时段
```


## Edge Cases

### UP主列表

1. **数据为空**：显示"暂无 UP主"提示
2. **网络错误**：显示错误提示，提供重试按钮
3. **搜索无结果**：显示"未找到匹配的 UP主"
4. **加载中滚动**：忽略滚动事件，防止重复请求
5. **最后一页**：显示"已加载全部 N 个 UP主"


### 推送历史

1. **今日无推送**：正常显示空状态提示
2. **重置按钮**：日期恢复到今天，而非清空


## Acceptance Criteria

### AC-001: UP主分页加载

- [ ] 后端 API 支持 `page`、`page_size`、`keyword` 参数
- [ ] 前端滚动到底部自动加载下一页
- [ ] 每页显示 20 条记录
- [ ] 加载过程显示状态提示


### AC-002: UP主后端搜索

- [ ] 搜索框输入触发后端搜索
- [ ] 搜索结果支持分页懒加载
- [ ] 清空搜索框恢复全量数据


### AC-003: 推送历史日期默认值

- [ ] 页面加载时日期自动设置为今天
- [ ] 数据查询自动使用今日日期
- [ ] 重置按钮恢复到今天日期


### AC-004: 性能要求

- [ ] UP主页面初始加载时间 < 2 秒
- [ ] 滚动加载响应时间 < 1 秒
- [ ] 搜索响应时间 < 1 秒
