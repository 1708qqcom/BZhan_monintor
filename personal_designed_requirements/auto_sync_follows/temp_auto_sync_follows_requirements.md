# Feature Requirements - 登录后自动同步关注列表

## Background

当用户将项目部署到新环境（如从GitHub克隆后启动），在前端扫码登录B站成功后，系统只保存了Cookie，但没有同步用户的关注UP主列表。导致用户登录后无法看到任何监控的UP主，需要手动添加或等待监控服务运行。

## Goal

在用户扫码登录成功后，自动调用B站API获取用户的关注列表，并将UP主信息写入数据库，实现"登录即用"的体验。

## User Story

As a: 新部署系统的用户

I want: 扫码登录后自动同步我的关注列表

So that: 无需手动操作即可开始监控我关注的UP主

## Functional Requirements

### FR-001 扫码登录成功后自动同步

**触发时机**：前端轮询 `POST /api/login/poll` 返回登录成功时

**行为**：
- 后端保存Cookie后，立即调用B站API获取关注列表
- 将UP主信息批量写入数据库
- 返回同步结果给前端

**约束**：
- 同步失败不影响登录成功状态
- 最多同步前50个关注的UP主
- 已存在的UP主跳过（不报错）

### FR-002 提供手动同步API

**端点**：`POST /api/ups/sync`

**行为**：
- 使用已保存的Cookie调用B站API
- 获取关注列表并写入数据库
- 返回同步数量和新增加的数量

**场景**：
- 用户关注了新的UP主后，可手动触发同步
- Cookie过期后重新登录，可手动触发同步

### FR-003 前端优化体验

**行为**：
- 登录成功后显示"正在同步关注列表..."
- 同步完成后显示结果
- 引导用户跳转到UP主管理页面

## User Flow

```
1. 用户访问 /bilibili-login 页面
2. 点击"获取二维码"
3. 使用B站App扫码确认
4. 前端轮询检测到登录成功
5. 后端自动同步关注列表
6. 前端显示"登录成功，已同步X个UP主"
7. 用户跳转到UP主管理页面查看
```

## Edge Cases

### EC-001 Cookie失效

**场景**：用户扫码成功但Cookie立即失效

**处理**：
- 同步失败，记录日志
- 返回"登录成功但同步失败，请稍后手动同步"
- 不影响登录状态

### EC-002 关注列表为空

**场景**：用户B站账号没有关注任何UP主

**处理**：
- 返回"同步成功，共0个UP主"
- 提示用户可以先去B站关注一些UP主

### EC-003 网络超时

**场景**：调用B站API超时

**处理**：
- 重试3次
- 失败后返回错误信息
- 建议用户手动同步

### EC-004 UP主已存在

**场景**：数据库中已存在某个UP主

**处理**：
- 跳过该UP主，继续同步其他
- 记录跳过数量

## Acceptance Criteria

### AC-001 登录后自动同步

**Given**：新部署的系统，数据库为空

**When**：用户扫码登录成功

**Then**：
- Cookie已保存到数据库
- 关注列表已同步到数据库（最多50个）
- 前端显示同步成功信息

### AC-002 手动同步API

**Given**：用户已登录，Cookie有效

**When**：调用 `POST /api/ups/sync`

**Then**：
- 返回同步数量
- 新增的UP主已写入数据库

### AC-003 同步失败不影响登录

**Given**：用户扫码登录成功

**When**：同步关注列表失败

**Then**：
- 登录状态仍为已登录
- 前端显示同步失败原因
- 用户可以手动触发同步
