# Feature Requirements - 定时调度功能

## Background

B站UP主视频监控服务需要核心调度引擎，自动定时检查关注列表中UP主的新视频，并通过飞书推送通知。

当前项目已完成：
- B站API调用模块（WBI签名、关注列表、视频查询）
- 飞书推送模块（新视频通知、错误告警）
- 扫码登录模块（Cookie管理）

缺少的核心功能：定时调度器，协调各模块完成自动化监控流程。

## Goal

实现监控服务的调度引擎，能够：
1. 定时执行监控任务（30分钟间隔）
2. 检测新发布的视频
3. 推送通知到飞书群
4. 记录历史避免重复推送
5. 支持优雅退出

## User Story

**As a** B站重度用户

**I want** 自动监控关注的UP主发布新视频

**So that** 第一时间收到通知，不会遗漏更新

## Functional Requirements

### FR-001 历史记录管理

调度器启动时从 `data/video_history.json` 加载历史记录。

历史记录数据结构：
```json
{
  "videos": {
    "BV1234567890": {
      "title": "视频标题",
      "up_id": 123456,
      "up_name": "UP主名称",
      "pub_time": "2026-08-02 14:30:00",
      "pushed_at": "2026-08-02 14:35:00"
    }
  },
  "updated_at": "2026-08-02 14:35:00"
}
```

每次监控循环结束后保存历史记录。

如果历史文件不存在或损坏，初始化空结构继续运行。

### FR-002 新视频检测

检查UP主最新视频（第一页，最多5个）。

对比历史记录：
- bvid 不存在 → 新视频
- bvid 已存在 → 已推送，跳过

返回新视频列表。

### FR-003 监控循环

单次监控循环流程：
1. 验证Cookie有效性
2. 获取关注列表（最多50人）
3. 遍历每个UP主，检查新视频
4. 推送新视频通知
5. 记录到历史
6. 保存历史文件

失败处理：
- Cookie过期 → 飞书告警 → 退出调度
- 单个UP主检查失败 → 记录日志 → 继续下一个
- 其他异常 → 飞书告警 → 继续下次循环

### FR-004 定时调度

启动调度器后进入无限循环：
1. 执行一次监控循环
2. Sleep 30分钟
3. 重复

配置项：`monitor.check_interval_minutes`

### FR-005 首次运行行为

首次启动时（历史记录为空）：
- 只记录UP主的最新视频到历史
- **不推送通知**

避免首次运行时批量推送大量旧视频。

### FR-006 UP主来源

优先使用B站账号关注列表。

支持手动添加特定UP主（通过Web后台或配置文件，后续Web功能实现后接入）。

### FR-007 历史记录清理

定期清理超过6个月（约180天）的历史记录。

每次保存历史时检查并删除过期条目。

### FR-008 优雅退出

支持 Ctrl+C 信号：
1. 捕获中断信号
2. 保存当前历史记录
3. 记录日志
4. 退出程序

## Edge Cases

### EC-001 历史文件损坏

**场景**：`video_history.json` 格式错误或内容损坏

**处理**：
- 记录警告日志
- 初始化空历史记录
- 继续运行（相当于首次运行）

### EC-002 Cookie过期

**场景**：监控过程中Cookie失效

**处理**：
- 发送飞书错误告警
- 退出调度器
- 等待用户重新登录

### EC-003 B站API限流

**场景**：请求频率过高被拦截

**处理**：
- BilibiliClient 已有重试机制（3次）
- 已有请求间隔控制（最小1秒）
- 单个UP主失败不影响其他UP主

### EC-004 飞书推送失败

**场景**：Webhook地址错误或网络异常

**处理**：
- 记录错误日志
- 继续监控流程
- 不中断调度

### EC-005 程序被终止

**场景**：用户按 Ctrl+C 或系统杀进程

**处理**：
- 捕获信号
- 保存历史记录
- 记录退出日志
- 正常退出

## Acceptance Criteria

### AC-001 基础功能

- [ ] 调度器能够启动并进入监控循环
- [ ] 历史记录正确加载和保存
- [ ] 能够检测出新视频
- [ ] 新视频成功推送到飞书

### AC-002 定时行为

- [ ] 监控循环间隔为30分钟
- [ ] 循环能够持续运行不中断（除非异常）

### AC-003 异常处理

- [ ] Cookie过期时发送飞书告警并退出
- [ ] 单个UP主检查失败不影响其他UP主
- [ ] 历史文件损坏时能够恢复

### AC-004 首次运行

- [ ] 首次运行只记录历史，不推送
- [ ] 后续运行正常推送新视频

### AC-005 历史清理

- [ ] 超过6个月的记录被自动删除
- [ ] 清理不影响正常监控

### AC-006 优雅退出

- [ ] Ctrl+C 能够正常中断程序
- [ ] 退出前保存历史记录
- [ ] 退出日志正确记录
