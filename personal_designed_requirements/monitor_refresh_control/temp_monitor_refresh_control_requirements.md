# Feature Requirements

## Background

当前监控系统通过后台线程每 10 分钟自动检查 UP 主是否有新视频发布。用户在 `/ups` 页面管理 UP 主时，无法感知：

1. 下次自动刷新的时间
2. 如何主动触发立即检查

这导致用户体验不佳，用户不知道系统何时会更新，也无法在添加新 UP 主后立即验证监控效果。

## Goal

在 UP 主管理页面提供：

1. **透明的刷新时间显示**：告知用户下次自动检查时间
2. **手动触发刷新能力**：允许用户主动触发立即检查

## User Story

**As a** 系统使用者

**I want** 在 UP 主管理页面看到下次刷新时间，并能手动触发立即检查

**So that** 我能知道何时会更新数据，并在需要时立即执行检查而不必等待定时任务

## Functional Requirements

### FR-001 显示下次刷新时间

- **描述**：在 `/ups` 页面顶部显示下次自动刷新的倒计时
- **格式**：`下次刷新: X分钟后` 或 `即将刷新...`
- **数据来源**：调用 `/api/monitor/status` 获取 `next_check_time`
- **更新频率**：页面加载时获取，之后每 30 秒自动刷新

### FR-002 手动触发刷新按钮

- **描述**：在页面右上角提供"立即刷新"按钮
- **位置**：在"添加 UP 主"按钮左侧
- **交互行为**：
  - 点击后按钮变为禁用状态，显示"刷新中..."
  - 调用后端 API 触发刷新
  - 刷新完成后恢复按钮，更新时间显示
  - 显示成功/失败提示

### FR-003 刷新状态反馈

- **描述**：刷新完成后告知用户结果
- **反馈内容**：
  - 成功：显示"已触发刷新，请稍后查看结果"
  - 正在检查中：显示"正在检查中，请稍后"
  - 监控未启动：显示"监控未启动"
  - 其他错误：显示具体错误信息

## Edge Cases

### EC-001 监控未启动

- **场景**：B 站未登录或 Cookie 过期导致监控线程未启动
- **处理**：显示"监控未启动"状态，刷新按钮点击后提示"监控调度器未运行"

### EC-002 正在执行检查时触发刷新

- **场景**：后台正在执行 `run_monitor_cycle()` 时用户点击刷新
- **处理**：API 返回 409 Conflict，前端提示"正在检查中，请稍后"

### EC-003 快速连续点击

- **场景**：用户快速多次点击刷新按钮
- **处理**：按钮点击后立即禁用，防止重复请求

### EC-004 刷新过程中离开页面

- **场景**：用户触发刷新后立即离开页面
- **处理**：后台刷新继续执行，不受影响

## Acceptance Criteria

### AC-001 时间显示功能

- [ ] 页面加载时显示下次刷新时间
- [ ] 时间格式为"X分钟后"，小于 1 分钟显示"即将刷新..."
- [ ] 每 30 秒自动更新时间显示
- [ ] 监控未启动时显示"监控未启动"

### AC-002 手动刷新功能

- [ ] 点击按钮触发后端刷新
- [ ] 按钮点击后立即禁用并显示"刷新中..."
- [ ] 刷新完成后恢复按钮状态
- [ ] 显示操作结果提示（成功/失败）

### AC-003 错误处理

- [ ] 监控未启动时点击刷新，显示明确错误提示
- [ ] 正在检查时点击刷新，显示"正在检查中"提示
- [ ] 网络错误时显示"刷新失败"

### AC-004 用户体验

- [ ] 按钮位置合理，不影响现有"添加 UP 主"按钮
- [ ] 时间显示位置醒目但不喧宾夺主
- [ ] 操作反馈及时、准确
